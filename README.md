# Steam Card Telegram Bot

Приватный репозиторий рабочего Telegram/FunPay бота для выдачи Steam-карточек.

## Состав рабочего проекта

- `bot.py`, `order_parser.py` — код бота.
- `start.bat` — запуск ASF и бота, проверка обновлений перед стартом.
- `update_bot.ps1` — безопасная синхронизация исходников с GitHub, журнал ошибок и резервирование перед обновлением.
- `run_bot.ps1` — загрузка пользовательских переменных Windows и защита от второго экземпляра.
- `backup_bot.ps1` — локальная резервная копия кода и runtime-данных.
- `requirements.txt` — Python-зависимости.

## Безопасность данных

Не добавляйте в GitHub реальные файлы `vouchers.json`, `inventory_cache.json`, `steam_session.json`, `funpay_config.json`, логи и резервные копии. В них могут находиться коды, ключи или сессии. Эти пути исключены в `.gitignore`.

В репозитории хранится только программа резервирования. Она создаёт копии локально в `C:\CardBot\резервные\`; сами копии никуда не отправляются. Не вставляйте настоящие токены и пароли в код, README, логи или сообщения.

## Установка на Windows 11

Эта конфигурация использует два каталога:

- `C:\CardBot_repo` — чистый Git-клон этого репозитория.
- `C:\CardBot` — рабочая папка с ботом, ASF и локальными JSON-данными.

Установите Git и Python, затем выполните:

```powershell
git clone --branch main https://github.com/koka7036-cyber/steam-cart-bot-private.git C:\CardBot_repo
py -3 -m pip install -r C:\CardBot_repo\requirements.txt
```

Скопируйте `start.bat`, `update_bot.ps1`, `run_bot.ps1` и `backup_bot.ps1` из `C:\CardBot_repo` в `C:\CardBot`. ASF должен находиться в `C:\CardBot\ASF-win-x64 (1)`.

В пользовательских переменных среды Windows задайте `TG_TOKEN`, `STEAM_ID`, `STEAM_LOGIN` и `STEAM_PASSWORD`. Скрипт запуска читает их из пользовательской области Windows и не выводит значения. Затем запускайте видимый `C:\CardBot\start.bat`.

## Автообновление и обработка ошибок

`start.bat` запускает `update_bot.ps1` перед ASF и ботом. Updater выполняет только fast-forward обновление из `main`, проверяет чистоту локального клона и синхронизирует `bot.py`, `order_parser.py` и PowerShell-инструменты. Он не заменяет JSON-файлы, настройки Steam/FunPay или коды.

Перед применением новой версии updater запускает локальную резервную копию runtime-файлов, затем сохраняет копию исходного кода в `C:\CardBot\update_backups\`. При ошибке загрузки или копирования остаётся предыдущий код. Если изменился `requirements.txt`, обновление кода останавливается; зависимости нужно обновить отдельно.

Обновление проверяется при каждом запуске `start.bat`, а не во время работы бота. Ошибки обновления записываются в локальный `C:\CardBot\auto_update.log`, ошибки работы бота — в `C:\CardBot\bot_errors.log`. Отдельная защита внутри `bot.py` блокирует второй экземпляр даже при ручном запуске, чтобы не возникал конфликт Telegram 409. На первом запуске мониторинга бот продолжает проверять непрочитанные чаты; ранее этот шаг мог пометить ожидающий заказ просмотренным без выдачи кода.

## Резервные копии

Для ручной резервной копии выполните:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File C:\CardBot\backup_bot.ps1
```

Копируются только известные файлы бота и локальные runtime-данные. ASF-бинарники, архивы и произвольные папки не копируются. Резервные копии остаются на этом компьютере и исключены из Git.


## Безопасность обработки выдач

Telegram-обновления обрабатываются в нескольких потоках, поэтому выдачи карточек сериализованы: перед отправкой бот повторно читает базу и проверяет, что код ещё не использован. JSON-файлы сохраняются через временный файл и атомарную замену, чтобы аварийное завершение во время записи не оставляло базу обрезанной.
