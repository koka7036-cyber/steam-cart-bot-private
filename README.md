# Steam Card Telegram Bot

Приватный репозиторий рабочего Telegram/FunPay бота для выдачи Steam-карточек.

## Состав рабочего проекта

- `bot.py`, `order_parser.py` — код бота.
- `start.bat` — запуск ASF и бота, проверка обновлений перед стартом.
- `update_bot.ps1` — безопасная синхронизация исходников с GitHub, журнал ошибок и резервирование перед обновлением.
- `run_bot.ps1` — загрузка пользовательских переменных Windows и защита от второго экземпляра.
- `backup_bot.ps1` — локальная резервная копия кода и runtime-данных.
- `funpay_orders.py` — журнал оплаченных заказов FunPay и защита от повторной выдачи.
- `sales_analytics.py` — тестируемая сводка кодов, отправленных предложений и состояния кэша.
- `playerok_monitor.py` и `playerok_orders.py` — изолированный read-only монитор сделок Playerok и локальный журнал.
- `requirements-playerok.txt`, `configure_playerok.bat`, `configure_playerok.ps1` — необязательная установка и настройка Playerok; они не меняют базовые зависимости бота.
- `requirements.txt` — Python-зависимости.

## Безопасность данных

Не добавляйте в GitHub реальные файлы `vouchers.json`, `inventory_cache.json`, `steam_session.json`, `funpay_config.json`, логи и резервные копии. В них могут находиться коды, ключи или сессии. Эти пути исключены в `.gitignore`.

`funpay_orders.json` создаётся только на рабочем компьютере. В нём нет трейд-ссылок или сессионных данных: он хранит номер заказа, количество наборов, статус и резерв карточек. Команда `/fporders` показывает последние заказы администратору, а `/fprelease КЛЮЧ` возвращает резерв в кэш, если заказ отменён до выдачи.

## FunPay: безопасный режим передачи

После предупреждения модерации бот не отправляет покупателям ссылки, коды или приглашения во внешние сервисы. Он только фиксирует оплату, резервирует карточки и сообщает администратору о поступивших данных.

- Основной режим настройки — `delivery_input_mode: "file"`.
- Получение трейд-ссылки из сообщения чата распознаётся для журнала, но автоматическая выдача остаётся отключённой.
- Вложение в чате отмечается как файл, но бот не скачивает и не обрабатывает его автоматически: текущий просмотр чата FunPay не даёт безопасного подтверждения содержимого вложения.

Не включайте `allow_chat_trade_url` без явного подтверждения FunPay для вашего товара и аккаунта. Правила площадки запрещают передачу контактов и ограничивают автоматическую выдачу товаров, для которых требуется дополнительное действие покупателя.

В репозитории хранится только программа резервирования. Она создаёт копии локально в `C:\CardBot\резервные\`, включая локальные конфиги и журналы ошибок; сами копии никуда не отправляются. Не вставляйте настоящие токены и пароли в код, README, логи или сообщения.

## Установка на Windows 11

Эта конфигурация использует два каталога:

- `C:\CardBot_repo` — чистый Git-клон этого репозитория.
- `C:\CardBot` — рабочая папка с ботом, ASF и локальными JSON-данными.

Установите Git и Python, затем выполните:

```powershell
git clone --branch main https://github.com/koka7036-cyber/steam-cart-bot-private.git C:\CardBot_repo
py -3 -m pip install -r C:\CardBot_repo\requirements.txt
```

Скопируйте `start.bat`, `update_bot.ps1`, `run_bot.ps1` и `backup_bot.ps1` из `C:\CardBot_repo` в `C:\CardBot`. ASF должен находиться в `C:\CardBot\ASF-win-x64 (1)`.

В пользовательских переменных среды Windows задайте `TG_TOKEN`, `STEAM_ID`, `STEAM_LOGIN` и `STEAM_PASSWORD`. Скрипт запуска читает их из пользовательской области Windows и не выводит значения. Затем запускайте видимый `C:\CardBot\start.bat`.

## Автообновление и обработка ошибок

`start.bat` запускает `update_bot.ps1` перед ASF и ботом. Updater выполняет только fast-forward обновление из `main`, проверяет чистоту локального клона и синхронизирует `bot.py`, `order_parser.py` и PowerShell-инструменты. Он не заменяет JSON-файлы, настройки Steam/FunPay или коды.

Перед применением новой версии updater запускает локальную резервную копию runtime-файлов, затем сохраняет копию исходного кода в `C:\CardBot\update_backups\`. При ошибке загрузки или копирования остаётся предыдущий код. Если изменился `requirements.txt`, обновление кода останавливается; зависимости нужно обновить отдельно.

Обновление проверяется при каждом запуске `start.bat`, а не во время работы бота. Ошибки обновления записываются в локальный `C:\CardBot\auto_update.log`, ошибки работы бота — в `C:\CardBot\bot_errors.log`. Отдельная защита внутри `bot.py` блокирует второй экземпляр даже при ручном запуске, чтобы не возникал конфликт Telegram 409. На первом запуске мониторинга бот продолжает проверять непрочитанные чаты; ранее этот шаг мог пометить ожидающий заказ просмотренным без выдачи кода.

## Резервные копии

Для ручной резервной копии выполните:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File C:\CardBot\backup_bot.ps1
```

Копируются только известные файлы бота и локальные runtime-данные. ASF-бинарники, архивы и произвольные папки не копируются. Резервные копии остаются на этом компьютере и исключены из Git.


## Безопасность обработки выдач

Telegram-обновления обрабатываются в нескольких потоках, поэтому выдачи карточек сериализованы: перед отправкой бот повторно читает базу и проверяет, что код ещё не использован. JSON-файлы сохраняются через временный файл и атомарную замену, чтобы аварийное завершение во время записи не оставляло базу обрезанной.

## Получение карточек через Telegram

Отправьте код (`SET...`) и трейд-ссылку Steam в одном сообщении или двумя отдельными сообщениями. После отдельного кода бот запоминает его для следующей ссылки; `/cancel` удаляет ожидающий код.


## Telegram: панель FunPay

В административной клавиатуре есть кнопка **«📋 Панель FunPay — сводка»**. Она открывает read-only сводку: статус подключения, время последнего пинга, доступные полные сеты в кэше, количество заказов по состояниям, резервы, случаи на ручную проверку, режим получения входных данных и состояние защитного отключения автовыдачи. В панели есть кнопки обновления сводки и просмотра последних заказов. Открытие панели не запускает выдачу и не меняет настройки.

## Продажи и состояние склада

Кнопка **«📈 Продажи и склад»** и команда `/sales` показывают остаток полных сетов, возраст кэша, неиспользованные коды по 1 и 5 сетов отдельно для FunPay и Playerok, а также число кодов, по которым Steam вернул ID торгового предложения. Меньше 10 полных сетов считается низким остатком, меньше 5 — критическим; кэш старше 6 часов отмечается как устаревший.

Отчёт не называет отправленное предложение завершённой сделкой и не выдумывает доход: Steam trade offer может ждать принятия покупателем, а цены/комиссии пока не записываются. Дневные показатели доступны для новых записей с временными отметками; старые коды учитываются только в общих итогах.

## Playerok: безопасный монитор сделок

Playerok подключается отдельным read-only модулем. После настройки он отслеживает события оплаченных сделок, новые сообщения, подтверждения, возвраты и проблемы, а затем показывает их в Telegram в кнопке **«🔵 Playerok — панель»**. Команды `/playerok_status` и `/playerok_orders` открывают сводку и последние записи.

Для безопасного сопоставления укажите точные ID двух уже существующих лотов в переменных Windows `PLAYEROK_ITEM_1_SET_ID` и `PLAYEROK_ITEM_5_SET_ID`. По названию лота количество сетов не угадывается; неизвестный или неоднозначный ID попадёт на ручную проверку. Один и тот же заказ определяется только по ID сделки Playerok. События могут повторяться и поэтому дедуплицируются.

Локальный журнал `playerok_orders.json` хранит только ID сделки/лота/чата, статус, количество сетов и время. Он не хранит session token, текст чата или трейд-ссылку. Если в сообщении замечена трейд-ссылка, сохраняется только факт её наличия. Если в одном чате несколько открытых сделок, ссылку нельзя автоматически привязать к одной из них.

### Первичная настройка Playerok

1. Сначала обновите бот обычным способом через `C:\\CardBot\\start.bat`.
2. Запустите `C:\\CardBot\\configure_playerok.bat` и внимательно прочитайте предупреждение перед согласием. Скрипт использует **неофициальную** библиотеку `PyPlayerokAPI`; Playerok предупреждает о рисках сторонних скриптов, имеющих доступ к данным профиля. Если не хотите принимать этот риск, не запускайте настройку.
3. Скрипт устанавливает необязательную библиотеку, принимает session token скрытым вводом и записывает его только в переменные среды текущего пользователя Windows. Токен нельзя отправлять в Telegram, писать в репозиторий или в логи.
4. Введите ID существующего лота на 1 сет и ID существующего лота на 5 сетов. Скрипт не создаёт, не удаляет и не редактирует объявления.
5. Закройте старое окно бота и запустите `C:\\CardBot\\start.bat`. Откройте **«🔵 Playerok — панель»** и проверьте состояние соединения и сопоставления лотов.

Если библиотека не устанавливается, авторизация отклоняется или Playerok показывает challenge/защиту, остановитесь и не используйте обходы, прокси или подмену дополнительных cookie. Монитор не должен мешать работе остального Telegram-бота.

**В этой версии мониторирование только для чтения.** Он не отправляет покупателю сообщения, не меняет статус сделки, не создаёт и не удаляет товары и не запускает Steam-обмен автоматически. Автовыдачу можно разрабатывать отдельно только после подтверждения допустимого сценария у поддержки Playerok и проверки реальных сделок. Неофициальная библиотека и доступ через сессию не поддерживаются Playerok официально.

## Ограничение автоматической выдачи FunPay

Автоматическая отправка кодов и ссылок покупателям FunPay отключена после предупреждения модерации. При распознанном заказе бот уведомляет владельца только в Telegram и не отправляет покупателю коды или внешние контакты. Не включайте выдачу снова, пока FunPay не подтвердит допустимый способ передачи товара.

## Разработка и тесты

Регрессионные тесты журнала заказов находятся в `tests/test_funpay_orders.py`. Они проверяют неоднозначное сопоставление заказов и защиту от повторной обработки входящих данных. GitHub Actions автоматически запускает компиляционную проверку и `python -m pytest -q` при изменениях в PR и `main`. Дополнительно Windows runner проверяет синтаксис скриптов обновления, запуска, резервного копирования и настройки Playerok PowerShell. Тесты не требуют действительных ключей Steam или FunPay.
